# G10: Matched Editor Composability

Protocol frozen before G10 outputs. Repository baseline is the current G8 commit. The existing G9 directory, including its untracked files in this checkout, is read-only historical evidence and its weaknesses are addressed here rather than silently rewritten.

## Question and design

Among low-rank BART `T_plus` editors with matched one-step success, does the G8-style decoder-directional content/structure fragility profile predict pure-latent success over repeated three-to-five-step application? Does it explain variation beyond rank and seed? This is an editor-level exploratory study; the planned factorial panel is rank 8/16/32 × seed 42/43/44 (nine editors). No optional regularized editor is included.

Only the independent `T_plus` operation is trained. Backbone, renderer, source schedule, target sequence lengths, optimizer, learning rate, clipping, initialization scheme and update count are shared. Training reuses the G3 BART `T_plus` 200-batch schedule: the same 3,200 source examples and fixed 1,600 G2 replacement occurrences; replaced examples receive the G3 two-stage 0.5/0.5 objective and others their original one-step objective. Each candidate makes 200 optimizer updates with batch 16, AdamW lr 1e-3, weight decay 0, gradient clip 1.0. This matches data and update budget; ranks differ in parameter count and compute, so it is not an equal-FLOPs comparison. Every editor is freshly initialized under the recorded seed; no G9 weights are reused.

The one-step matching set is a fresh, locked 80-world IID plus 80-world template-OOD set. It is evaluated before the repeated-composition set. An editor is retained only if its one-step joint success is at least 95% in each matching stratum. This gate fixes the cohort before composition-test model output is generated. The test set is a separate fresh 80 IID plus 80 template-OOD worlds, all complete five-step paths. Both sets contain only legally readable recorded plans, use a common start frame at event offset +1, and require all five frames to be valid. OOD means a held-out template family, not natural language generalization. Full-fact keys are checked against the old train/dev/calibration/test worlds and across all new sets. The hidden world slots are scoring-only; inference receives the rendered source and frozen editor.

The source schedule and stepwise loss are copied in meaning from the G9 BART run and G3 training engine. The training update count is fixed at 200 for all nine editors; there is no test-based checkpoint selection. The dev matching set selects no checkpoint; it selects only the predeclared matched cohort. Test one-step results are reported separately and are not used to alter the cohort.

## Measurements

For each retained editor, evaluate one encoding followed by five repeated `T_plus` applications with the original encoder attention mask and greedy BART decode at each step. Intermediate decoded strings are diagnostic only and never re-enter the latent chain. At each step save the full text, target frame, joint/date/person/fact/termination results, hidden-state distance to the independently encoded gold at that step, residual norm, and cosine between consecutive residual means. Report endpoint success at steps 1–5, the first failed step, and trajectory success through each horizon.

At each currently correct pure-latent state at steps 1–4, perform the G8 directional scan. Normalize every candidate direction to the actual next-editor residual's masked token-by-hidden L2 norm. Directions are editor-forward, editor-reverse, radial-orthogonal random, toward-gold, and editor-orthogonal random. Decode at alpha 0.25, 0.5, 0.75, 1, 1.5, and 2; refine the first semantic-corridor failure interval twice, as in G8. Preserve every output and score. The prespecified fragility measure is trapezoidal area over alpha 0..2 of one minus content/structure compatibility (readable controlled parse, all non-date facts retained, normal end); alpha 0 is assigned zero failure because the scanned state is already correct. The main directional compatibility score is forward failure-area minus the average of the two orthogonal-random control areas. Also report all five directional curves, semantic corridor success, and first-failure radii. A failure-area metric uses the complete sampled curve and does not assume monotonicity.

Primary editor-level outcome: mean pure-latent endpoint success at steps 3, 4, and 5. Secondary outcomes: each horizon, trajectory success, and first-collapse step. Analyze editor-level raw points with Spearman correlation and a small OLS including fragility, step-1 rate, rank, and seed indicators. With at most nine editors, intervals/p-values are descriptive and no significance claim is planned. Report the raw editor rows and leave the small-sample limitations explicit. World-bootstrap intervals summarize each editor's rates but do not create additional independent editors.

The existing G8/G9 scans and the previously completed Joint-rank16 result are historical context, not matched-editor observations, because they use different worlds and/or training objectives. A single joint-task editor can show that the joint endpoint task is learnable; it cannot establish that independent semantic operators compose.

## Execution and audit

Use one Slurm GPU per job and at most two concurrent jobs. All GPU work runs under `sbatch` plus `srun`. Lock protocol, configuration, generated worlds, target paths and code hashes before model training/evaluation. Then train the nine fixed candidates, run the one-step matching gate, freeze retained IDs, evaluate repeated chains and G8 profiles, analyze, and audit. Keep complete denominators, unresolved parses and all failure outputs. Preserve old experiment paths unchanged. Upload only this new experiment directory and necessary editor checkpoints/results on an independent branch; no base-model weights or secrets.
