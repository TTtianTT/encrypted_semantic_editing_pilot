| UV 秩 | R_30 中位数 | R_100 | 第 10 / 30 / 100 步距离（R_w 单位，3 个 seed 的范围） |

- **锁定的读法："未解释"**。秩升高后衰减没有变慢，反而离金标准编码更远、更快。
- **探针设计缺陷（Claude 的实现问题，必须如实报告）**：计划要求"从槽位读出上一步的名字"。但在 plus 链上，上一步的名字是当前名字的固定函数（上一步 = 当前 − 1 mod 3）。所以"旧名字"探针和"当前名字"探针是同一个分类器，只是类别标签换了一下，准确率完全相同：每个编辑器都是 0.44–0.86。这个指标区分不了"旧名字残留"与"当前名字仍可读"。表面上的下降（0.75 → 0.67 → 0.49）应理解为槽位整体偏离更远，**不能当作残留下降的证据**。
- 读法的结论不受影响：衰减本身没有变慢，"未解释"成立。但 §9 不能引用残留这一半。

### E2b：用随机方向链补测残留（AMENDMENT_02，探索性，CPU，不解码）

- **设计**：每步方向随机（plus 或 minus）。这样上一步名字不再是当前名字的函数；已知当前名字时，"最后一步的方向"的机会水平为 0.5。方向探针在 train 上拟合，C 在 dev 上选。

| UV 秩 | 方向探针：第 1–8 / 9–30 / 31–100 步 | 当前名字探针：第 1–8 / 9–30 / 31–100 步 |
| --- | --- | --- |
| 32 | 0.99 / 1.00 / 1.00 | 1.00 / 0.96 / 0.65 |
| 128 | 1.00 / 1.00 / 1.00 | 1.00 / 0.95 / 0.60 |
| 满秩 | 1.00 / 1.00 / 0.94 | 1.00 / 0.91 / 0.50 |

（3 个 seed 的中位数。）

- **结果**：槽位几乎完美地保留了上一步从哪里来（视野内 ≥ 0.99，远高于 0.5）。秩从 32 提到满秩，残留并不下降。
- **读法**（运行前写定，`results/e2b.json`）：残留不下降，维持"**未解释**"。
- **可以如实说的**：在每个秩上，编辑器的写入都留下前一步的痕迹，而且提高秩既不能去掉它，也不能减缓衰减。所以"写入秩不够"不是原因。至于残留本身是否就是瓶颈，这组数据不能区分。
- **对照的说明**：干净编码不含历史，方向探针在这上面输出近乎恒定的类别（判为 plus 的比例在各编辑器间为 0.04–0.83）。这符合"无信息"的预期，不是准确率。
