# 模型复核（不是人工标签）

由本轮执行模型阅读配对原句、逐步目标和输出，便利抽样，不估计总体准确率，不改变冻结评分器或任何主分母。没有真人审核。

- 新IID0009，计划明天交付8个传感器：G2首步直接写yesterday、第二步仍yesterday；G3依次today/yesterday，作者、接收者、数量及“记录不证明发生”均保留。支持已训练两步中间语义修复。
- 新OOD0011，取消的搬运2个包裹计划：G3第一步将in two days改tomorrow正确，第二步仍tomorrow而不是today。第一步恢复不保证第二步正确。
- 新IID0000，否定计划给Frank四个传感器：G3时间后转人称得到today及Carol's，否定和计划保留；G2两步日期均提前。这是跨操作恢复案例。
- 新IID0023，取消的交付9张票计划：G3时间步正确，随后出现“tomorrow in two days”的日期冲突，解析未决合理；不将全部未决都视为相同的已确认错误。
- 新OOD0013，报告未交付7个包裹：G3时间往返第二步将7变4，并保留错误的three days ago。可明确确认数量损坏；取消/否定并非本例错误来源。
- 新OOD0050，取消的否定搬运2个包裹计划：逐例结构化检查显示往返终点写3个包裹，另有日期错误。与报告单列的第二条G3非日期事实损坏对应。
- 新OOD0003，第三人称的2个包裹计划：G3改日期到tomorrow，但引入“that the note describes for this record...”并破坏原证据免责声明的结构。完整解析失败；至少存在文本结构退化，不能因此推算其他未决样本的真实语义错误率。

以上案例说明收益和限制同时存在。新IID完整两步成功不等于OOD、三步、往返或所有事实都恢复；不作容量必然限制或离开流形的机制结论。
