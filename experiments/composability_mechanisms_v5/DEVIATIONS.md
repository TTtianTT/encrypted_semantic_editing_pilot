1. **2026-11-24，confirm6 多句式数据的去重口径与句式分配（B1、B4；锁定前）**。
   - 原因：第一次生成（作业 72952）在"全部历史渲染"中额外计入了 v5 GR 闸门的渲染，即 v5 的每个 train/dev world 在全部 36 个句式下的渲染。这些文本没有写成数据文件，只在重建闸门中编码再解码，从未用于训练或标定。计入之后，字段少的留出句式几乎没有新鲜文本：weekday-mt 的 160 个 world 全部落在句式 10 上，hour-mt 落在 2 个句式上。
   - 做法：
     - 历史只计数据文件中的渲染：v1–v5 的 `renders.jsonl`（包括 confirm5 与 v5 的多句式 train/dev/confirm5），以及更早的 four-domain、canonical、manifold、operator-residual 文件。这与计划"全部历史渲染（包括 confirm5 与 confirm5-mt）"的文字一致。
     - 留出句式按种子顺序轮流填充：对当前句式抽取字段，直到该句式下全部状态的渲染都与历史和其他新 world 不重合。若某句式连续 20000 次都抽不到，记为耗尽并跳过。
     - 新 world 之间的文本也互不重合（比 v5 DEVIATIONS #4 更严）。
   - 结果（作业 72955，审计 72956 通过）：
     - weekday-mt：8 个句式各约 20 个 world，句式 0 只有 1 个后耗尽。
     - month-mt：9 个句式，句式 1 有 1 个、句式 30 有 2 个，其余 13–28 个。
     - hour-mt：8 个句式各约 20 个 world，句式 3 只有 1 个。
     - 含干扰词的 world：weekday-mt 60、month-mt 82、hour-mt 59。
   - 影响：字段少的留出句式（只含 {o} 的句式 0、1、3）几乎不出现，M 的结论只覆盖字段较多的留出句式。报告中列出各句式的 world 数。

2. **2026-11-24，A.8.3 的单层编辑器判据（锁定前）**。
   - 原因：计划要求在两跳合成指针任务上"单层编辑器 ≥ 0.5"。这个判据原则上做不到。单层注意力可以抵消当前名字（UV 项），再把注意力均匀地放在其余 M − 1 个名单名字上，相对 L2 为 (M − 2) / (2(M − 1))，M = 3 时为 0.25，任何 M 都 < 0.5。只有逐 token 编辑器（Tok）的下限是 0.5。自检作业 72958 中，单层 Att1 正好收敛到 0.277。
   - 做法：判据改为 Att1 ≥ 0.2（其下限为 0.25）且 Tok ≥ 0.45（其下限为 0.5）；Att2L ≤ 0.05 与 OR ≤ 0.01 不变。
   - 影响：自检仍检验"单层做不到第二跳"，判据按单层的理论下限设定。

3. **2026-11-24，A.8.3/A.8.4 的合成任务构造（锁定前）**。第一版合成任务（作业 72957）里，名单 token 与槽位用同一个名字向量。逐 token 的线性编辑器无法只改槽位而不改名单，任务对任何编辑器都不可解（Tok 0.91，Att2L 0.58）。改为沿用 v4 的指针任务构造：名单名字在名单子空间，槽位名字在槽位子空间；同一序列的名字共享随机分量；每个位置带位置标记。与 v4 的区别是，槽位只含当前名字的槽位编码，不含位置标记，必须先在名单中找到当前名字，再取下一个。影响：无（这是自检任务本身的构造）。

4. **2026-11-24，锁定前作业顺序（B9；锁定前）**。自检 A.8.3 还在排查时，先提交了不依赖 K 编辑器的锁定前 GPU 作业：编码、GM、两个骨干的多句式标定、上下文标定、M 与 C 的编辑器训练，以及 T5Gemma 的模拟与冒烟测试。K 的训练、BART 的模拟与冒烟测试等自检通过后再提交。影响：只改变作业编排。

5. **2026-11-24，C 单元"已收敛"名单与数值规则不一致（B6；锁定前）**。

9. **2026-11-24，A.8.3/A.8.4 自检的优化设置（锁定前）**。
   - 原因：按计划的训练设置（AdamW 1e-3、batch 16），Att2L 在两跳合成任务上停在单层解：held-out 相对 L2 约 0.27，0.25 是单层下限。8000、20000、40000 次更新都如此，与名字是否共享随机分量无关（排查作业 72961、72976–72980，`local/dbg/`）。
   - 唯一在 20000 次更新内稳定越过平台的设置是 lr 3e-3、batch 64：held-out 0.036，训练损失 0.001（作业 72980）。lr 3e-3、batch 16 跑 60000 次会越过平台，但不稳定（最低 0.027，最后 0.108）。
   - 做法：自检 A.8.3/A.8.4 对四种编辑器（Att2L、Att1、Tok、OR）统一用 AdamW lr 3e-3、batch 64、20000 次单步更新。它检验的是"结构能学会第二跳"。
   - K 的正式训练仍按计划（附录 A.4/A.6：AdamW 1e-3、batch 16、4000/8000 次更新），不改。
   - 影响（报告中必须写明）：在合成任务上，计划的训练设置不足以让 Att2L 学会两跳。因此 K2 若判为 H-horizon，不能区分"结构表达不了"与"在给定训练预算下没有学会"。K1（oracle 路由）可以帮助区分。

10. **2026-11-24，λ\_ctx 的标定（B6、附录 A.3；锁定前）**。
    - 结果：上下文标定（作业 72965）的探针显示，解码器从不跟随上下文。weekday 的 2688 个、month 的 8448 个探针中，两类替换（槽位保持 x、上下文换成 x + m，以及补集型）的解码状态 100% 等于槽位的状态，0 个跟随上下文。
    - 因此似然对 λ\_ctx 几乎完全平坦。任何 λ\_ctx > 0 都只会降低观测标签（槽位状态）的概率，精确的极大似然解是边界 λ\_ctx = 0。
    - 第一版拟合（LBFGS，softplus 参数化）停在平坦区的任意值上（weekday 0.0015，month 28.9），是数值假象。
    - 做法：
      - `lib6.fit_lam_ctx` 改为精确求解：在 {0} 与对数网格上求 NLL 的最小值，平局取最小的 λ，再在相邻网格点之间做黄金分割细化；同时报告 λ = 0 处的导数。重新运行上下文标定（作业 72986），在 BART 的模拟之前完成。
      - 若 λ\_ctx = 0，槽位+上下文读出与只看槽位完全相同，CT1 的提升恒为 0，Q19 由构造判为 H-slot。报告中如实写明：按计划的探针，解码器的状态读取完全由槽位决定，上下文中干净的状态信息不起作用。
      - 锁定前另行声明一个探索性分析（不参与判定）：上下文漂移 min\_y d\_ctx(h\_t, y)，写入锁定的模拟文件。在 CT1/CT2 中，对槽位读出预测"成功"的 world，计算最大漂移对观测失败的 AUC。它检验未收敛编辑器的误判是否来自离开规范流形的漂移，而不是上下文中的状态信息。
    - 影响：Q19 的确认性判定退化。探索性分析给出机制上的信息。

11. **2026-11-24，C 单元中权重相同的格子（B6；锁定前）**。
    - 现象：新训的 C3n600（seed 42/43/44）与 v1 的 C3（600 次更新）用的是同一个 seed、同一批次序列和同一优化器，结果逐位相同：两个域上的 dev L2 比值相同到 16 位，例如 weekday s42 都是 1.99769，month s42 都是 2.44345。另外，month C3n300 s42 的 dev 准入率是 0.893，低于 0.90，按规则重训到 2 倍更新，取的是第 600 次快照，因此它与 C3n600 s42 也相同。
    - 做法：按计划保留全部格子，判定口径不变；`analyze.c_unit` 另外输出 `exploratory.identical_cells`，列出潜空间轨迹完全相同的格子组。报告中同时给出去重后的格子数。
    - 影响：CT1 中有重复的格子。CT1 的 world-cluster bootstrap 按 world 重抽样，重复格子只增加权重，不增加独立样本。由于 λ\_ctx = 0（#10），CT1 的提升恒为 0，重复不影响 Q19 的判定。探索性的漂移 AUC 与首次读错计数也包含重复。
    - 附带的信息：C3n600 与 v1 C3 逐位相同，说明训练流程在 v1 到 v6 之间可以精确复现。
